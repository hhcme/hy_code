### 1.2 实际护栏

全局最多两个独立读取或一个独占写操作；公共 Git 管理目录作为共享锁范围。每次 Git stdout 最多 8 MiB、stderr 最多 256 KiB；本地命令 20 s、网络命令 90 s，取消/超时只终止自有进程组，TERM 后 500 ms 升级 KILL 并等待回收。输出超限不把前缀当完整结果。

状态/提交文件列表最多 20,000 项，引用最多 10,000 项，索引快照最多 64 MiB。差异输入合计 8 MiB、源码投影 20,000 行、EOF 注记另限 32 个、单行 16,384 UTF-16 单位；超限、二进制、链接、子模块或冲突显示类型/对象/原因。差异正文同用现有编辑器的 14 pt 系统等宽字，CoreText 后台测量 CJK/emoji/Tab 字形宽度，避免按 UTF-16 长度猜测水平可滚动范围；测量缓存最多 1,024 项。只保留活动差异投影，其他标签保留定位身份；历史缓存最多 2,000 条，操作控制台最多 100 条、每条 8 KiB。大文件候选使用后台流式 SHA-256，不能用局部页构造提交。实际大型仓库延迟、扫描负载与 UI 峰值仍待单独测量。

### build 55：块级动作与贯穿连接带

用户明确要求参考图中的块级箭头、复选框、左右对应连接，并指出中缝又宽又有框。动作语义核对了 WebStorm 官方[差异编辑器](https://www.jetbrains.com/help/webstorm/differences-viewer-for-files.html)与[部分提交](https://www.jetbrains.com/help/webstorm/commit-and-push-changes.html)说明：右侧勾选决定本次提交范围，未选修改保留；左侧箭头将当前块还原为左侧版本。这里只记录公开行为，不复制第三方实现或截图内容。

- 左侧 `»` 对工作区/未暂存的完整可编辑文本还原一个差异块。`GitBlockEdit` 在后台计算真实 UTF-16 替换范围，入口绑定绘制时差异 ID/请求代次，再复核文档修订、原文字节和组合输入状态；只经共享 `NativeTextEditor.insertText` 和独立 Undo 分组修改正式文档，允许普通撤销/重做，保存仍沿用原所有者。

2. 展开底部 Git，查找分支、作者、路径或某次提交，查看提交详情、改动文件和历史差异，再返回当前编辑位置。
3. 创建和切换分支、获取远端状态、拉取和推送；有未保存内容、分叉或冲突时，保留工作并给出可继续的入口。
4. 临时保存未完成改动，恢复后继续工作；清楚区分提交选择、Git 暂存区、Git 贮藏和应用自己的搁置记录。

打开项目只触发受限的本地仓库发现和状态读取，不自动提交、联网、切分支、运行项目 hooks 或改写 Git 配置。用户的每次写入操作应有明确目标和结果；正常提交按钮本身即可表达提交意图，不为每次普通提交重复增加确认弹窗。

### 3.1 两个独立工具与布局状态

- 新增“提交”工具，默认归左上；现有“Git”工具归左下，承载日志/控制台。沿用现有长按移动、排序、菜单和四角单活动工具规则。
- 默认启动布局继续是左上项目树、右上 Codex。用户打开“提交”时替换左上当前工具；展开 Git 底栏不关闭提交或中央差异。不能为了模仿参考图自动收起 Codex。
- 两张参考图分别对应底部 Git 隐藏与展开；收起底栏后中央差异恢复高度，左侧消息区保留用户设置。四角移动后的内容仍能工作。
- 建议初次展开提交约 300 pt 宽、底部 Git 约占可用内容高度 40%；这是原型起点，最终受既有最小尺寸和布局测试约束。记忆用户调整，不能每次选择文件重置。
- 宽度不足时优先把提交详情切成可切换子页，提供手动切统一差异入口；不强迫隐藏 Codex，不让主要操作越出窗口。各面板、列表和差异区分别滚动。
- 分支筛选、历史选中提交、树展开、消息草稿和差异位置按仓库/会话保存；不同仓库不混用草稿和勾选项。历史差异按对象身份定位，不能在工作树变化后变成当前文件。

### 3.2 视觉和输入

复用[现有视觉基线](VISUAL_ALIGNMENT.md)：纯色外框和内容底、圆角面板、紧凑分段标签、细分隔、固定透明滚动槽、系统 UI 字体与原生等宽编辑字体。高亮、选中、悬停、按下和键盘焦点应可区分；新增/删除/修改同时使用标记与色彩。保持深浅主题和减少动态效果。

分支树、文件列表与日志支持方向键、Home/End、Enter、Space 勾选和 Escape 关闭局部菜单；文本输入优先处理 IME。建议提交入口使用 ⌘K、推送使用 ⇧⌘K，差异上一/下一处使用 ⇧F7/F7；接入前检查现有快捷键，功能键保留菜单替代。提交消息内 Enter 换行，不能误触提交；实际执行快捷键在按钮/菜单标注。VoiceOver 应读出文件状态、勾选状态、比较两端和操作目标。

## 4. 仓库发现、身份和权限

首批以当前项目中的一个活动工作树为单位，不要求同时提交多个仓库。项目根是仓库子目录时，必须显示真实仓库根；若它在当前授权范围之外，先提供用户主动扩大授权的入口，不静默向祖先目录扩权。

- 识别普通 `.git` 目录和 worktree 使用的 `.git` 文件；工作树根、实际 Git 管理目录和公共管理目录分开建模。链接指向外部路径不等于获得访问权限。
- 不无限递归扫描寻找仓库。嵌套仓库/子模块显示独立边界和仓库选择入口，父仓库只处理相应引用变化，不把子仓库文件按普通父仓库内容提交。跨仓库批量操作后续另行验收。
- 初始空仓库显示“尚无提交”；分支没有 upstream 显示“未设置上游”；浅克隆或缺失历史说明覆盖范围。裸仓库可明确不支持工作树操作，不伪造空的正常状态。
- 仓库不可访问、Git 工具不可用、版本不兼容、对象损坏、不安全目录或锁被占用时原位报错并可重试；不自动安装工具、不写全局信任、不删除 `.git` 锁文件。
- 当前采用已安装 Git CLI，声明 2.48+；配置、进程与许可边界见第 1.1 节和 [ADR 0016](adr/0016-native-git.md)，不引入 libgit2 或 gix。

## 5. 更改列表与提交选择

### 5.1 列表信息

按目录树和平铺两种方式查看，支持路径筛选、刷新、展开/折叠、定位当前文件。每项显示文件图标、文件名、仓库相对路径和状态：新增、修改、删除、重命名、未跟踪、冲突、类型/权限变化；暂存和未暂存可以同时存在，不能用一个“已修改”覆盖掉区别。重命名显示旧路径到新路径，同名文件可以区分。

未跟踪文件单独分组，默认不选；被忽略文件默认隐藏，显式查看后也不自动加入。跟踪文件首次进入提交面板同样不自动全选，提供明确的全选和清除；外部新产生的改动不继承已选状态。行的焦点、打开差异与勾选是三个不同动作：单击名称查看差异，复选框或 Space 改变范围，双击/“打开源文件”进入正常编辑。

分组复选框有全选、未选、部分选三态。筛选后明确“选择筛选结果”与“选择全部改动”，同时显示可见数、已选数和总数，不能让隐藏文件悄悄进入提交。刷新保留仍有效的选择；选中内容发生变化时标记待重新审查，不能仅凭相同路径继续提交新内容。

### 5.2 默认勾选模式与真实暂存区

**建议默认采用接近参考图的“选择本次提交”模式。** 勾选只表示提交候选，不立即执行 stage；取消勾选不执行 unstage，也不丢弃正文。当前支持完整文件及第 1.2 节范围内的差异块选择。另提供明确的“暂存区”视图，支持 stage/unstage 和只提交真实已暂存内容，不把两种模式的复选框混为一谈。

Git 的普通提交以 index 为输入，工作树、index 与 HEAD 是不同版本；差异比较也必须明确端点。依据 [Git commit](https://git-scm.com/docs/git-commit) 与 [Git diff](https://git-scm.com/docs/git-diff) 的契约，本产品需要满足以下可验收结果，具体事务实现另写 ADR：

- 选择文件 A 时，未选择文件 B 的暂存与工作树内容不被提交、撤销或覆盖；不能用全库 add/reset 实现勾选提交。
- 同一文件同时有已暂存版本和后续未暂存更改时，分别可查看。首批如不能证明选择模式保留两者，阻止该次选择提交并引导用户使用暂存区视图，不能默默提交整文件或悄悄更换模式。
- 暂存区模式的提交只使用已核对的 index；未暂存和未跟踪内容不随之加入。默认选择模式与暂存区模式均显示当前采用的来源和最终候选。
- 差异块选择必须绑定基线、路径、修订和具体内容；块失配就重新生成预览。仅被选中的修改进入候选，未选修改仍留在原来的暂存/未暂存层。重命名、二进制、模式变化或无法安全拆块的项目只允许整项处理并说明原因。
- 空白忽略、折叠上下文或统一视图只影响显示，不改变提交内容。忽略空白后不可见的变化仍计入范围，并可切回精确预览。
- 首次提交、删除、重命名、大小写变化、可执行位变化和符号链接项分别验证。链接只展示 Git 保存的链接信息，不跟随读取目标；当前原生编辑不支持的文件不能因此变成可编辑。

首批可以没有自定义 changelist；后续若增加，它只组织候选，不冒充 Git 分支、index 或 stash。

### 5.3 文件动作与丢弃范围

列表/源文件菜单提供打开、定位项目树、查看工作区/暂存差异及文件历史；stage、unstage 和丢弃使用不同名称，不用同一个“回退”承载多种含义。

- “取消暂存”只改变 index，保留工作版本；“丢弃未暂存更改”明确恢复到 index；“恢复到 HEAD”需说明会同时影响该项的暂存与工作版本，不能默认把两者混用。
- 丢弃前展示具体路径、来源和范围，核对未保存缓冲及磁盘版本；按本文档保护规则取得写入权后再执行。不可普通撤销的操作需要一次明确确认；普通审查、勾选或取消勾选不产生丢弃。
- 未跟踪文件不以“恢复”名义删除，不顺带执行全库 clean；删除、被忽略内容清理和恢复保障另行定义。新建 `.gitignore` 或修改忽略规则也是可审查的普通文件修改，不直接覆盖已有缓冲。
- 整文件安全丢弃纳入 G2；逐块丢弃纳入 G3。未能完整预览或证明精确范围时不提供块丢弃，不能把截断片段当作原文件。

## 6. 中央差异视图

### 6.1 比较来源

| 场景 | 左侧 | 右侧 | 写入权限 |
| --- | --- | --- | --- |
| 默认本地更改 | 当前 HEAD；空仓库为显式空基线 | 当前工作版本；存在打开缓冲时显示该缓冲及未保存标记 | 只有当前工作版本允许进入编辑 |
| 已暂存更改 | HEAD / 空基线 | index 快照 | 两侧只读 |
| 未暂存更改 | index 快照 | 当前工作版本 | 只有当前工作版本允许进入编辑 |
| 某次提交的更改 | 明确选择的父提交；根提交为空基线 | 选中提交 | 两侧只读；合并提交须标明比较的父提交 |
| 两个提交/分支比较 | 用户选定的左端对象 | 用户选定的右端对象 | 两侧只读；完整对象身份固定 |
| 贮藏/搁置预览 | 对应记录的基线 | 捕获内容 | 两侧只读，恢复是单独动作 |

“当前版本”旁必须标明工作区、暂存区或提交短哈希；完整路径、完整哈希和时间可在详情查看。工作区未保存内容可供审查，但不会直接进入 Git 提交；提供“保存选中文件并刷新”后重新确认范围，不为了提交隐式保存其他草稿。

### 6.2 呈现和操作

- 默认左右分栏、各自行号、对应行对齐、增删改行底色、行内字符高亮和块连接；未变区域可折叠/展开，边缘标注增删改，不只靠色彩表达。
- 提供“第 n / N 个文件”“第 n / N 处差异”、上一/下一文件、上一/下一差异、打开源文件、左右/统一视图、空白选项和设置。到末尾不悄悄跨文件或循环；是否继续由明确动作决定。
- 同步纵向滚动按匹配行/块映射，不直接按像素比例；换行或上下文折叠不破坏对应。横向滚动和长行需可用，左右比例和视图偏好可记忆。
- 当前工作版本编辑必须复用现有正式文档、修订、IME、Undo 和自动保存，不能在差异页新建第二份可写文本。块反向应用/丢弃需走版本校验与原生事务，历史侧不能编辑。
- 块间箭头、复选框和边栏按钮必须有动作说明与目标侧提示；选入提交、恢复旧内容和打开源文件是不同动作，不能根据相似图标执行意外覆盖。
- G1 可以先交付只读对比及打开源文件；同页编辑、差异块选择和安全的块操作是后续 G3 的独立验收项，不能以只读视图宣称已完整复现截图效果。
- 外部更新或保存引起端点变化时刷新工作区比较，并废弃受影响的提交勾选；历史快照保持原版本。过期结果不得替换用户后来打开的文件。
- 图片、视频、二进制、LFS 指针、子模块及超预算文件先显示类型、对象/大小/状态和无法逐行比较的原因；不自动下载 LFS 内容、运行 diff driver 或把二进制按文本改写。图片并排视觉比较可另列后续能力。

## 7. 提交消息、提交与推送

消息区支持多行、IME、独立撤销、仓库范围草稿与历史消息选择；标题/正文提示不强制指定团队格式。默认不调用模型生成消息，也不把仓库内容发往外部服务。作者身份缺失时提供用户主动配置当前仓库的入口，不能代填身份或默改全局配置。

“修正上次提交（Amend）”默认关闭；开启后展示将被替换的提交和消息，保留原消息草稿以便退出。没有 HEAD 时禁用；已发布/共享风险在开启或执行时明确提示。amend 与后续强推是两个动作，不能自动串联。

提交前至少校验活动仓库/分支、HEAD、index、选中快照、未保存状态、冲突状态和消息非空。选中文件未保存时要求保存并重新审查或取消；快照已过期则停止并显示差异，不能自动提交较新的内容。提交按钮禁用时说明具体原因，单纯无改动不用报错。

- **提交**：产生本地提交后核对新对象与分支状态，显示短哈希、实际范围和剩余更改。失败保留消息与仍有效的候选，不误报成功；不承诺已经运行所有检查。
- **提交并推送**：先提交，再展示/使用用户已确认的远端、源分支、目标分支和 upstream。提交成功、推送失败时显示“本地已提交，推送失败”，提供仅重试推送，不重复创建提交。
- **推送**：展示待推送提交范围和目标；默认只操作当前明确分支，不附带推送全部分支或标签。无远端/上游时进入显式配置流程。远端拒绝后保留本地状态，不能自动拉取、改写历史或强推。
- hooks、签名或清理/过滤器可能执行外部代码，需要明确的项目信任和工具执行策略。未获信任时说明不能完成的步骤，不通过静默关闭 hooks、跳过验证或取消签名伪造成功。
- 受信任的 hooks/过滤器若改变候选或工作版本，必须重新核对范围与内容；新增变化不能悄悄并入原选择。失败后保留其实际生成的改动并提示，不擅自回滚用户文件。
- 终止请求和操作结果分开：写入已到提交点时先查明是否已完成；网络断开时先核对远端结果。不能把用户点击“取消”一律显示为“没有产生修改”。

## 8. 底部 Git 日志与控制台

### 8.1 三列日志

| 区域 | 需求 |
| --- | --- |
| 左列分支树 | HEAD、本地分支、按 remote 分组的远端分支、标签；搜索分支/标签；标记当前分支和 upstream；允许收起 |
| 中列历史 | 拓扑图、提交标题、分支/标签装饰、作者、时间和短哈希；按需分页；选中不改变工作树 |
| 右列上部 | 选中提交的改动文件、状态、路径及增删统计；单击文件进入历史差异 |
| 右列下部 | 完整消息、完整哈希、作者/提交者及各自时间、父提交、引用与签名信息（仅实际可验证时） |

默认查看当前分支日志，可切全部引用；分支选择用于筛选，双击也不能直接 checkout，切换由明确菜单动作触发。过滤支持提交文本/哈希、作者、日期和路径，按需组合，刷新后说明过滤条件；没有结果与加载失败分开。路径历史的重命名跟随、合并父提交及浅历史边界须标明，不暗示历史完整。

合并提交的线条和父子关系必须来自仓库对象；分页处保留连接信息，不猜测或伪造节点。加载更早记录保留选中提交和滚动锚点；查找某个哈希按需定位，不全量装载所有对象。提交详情和差异用同一个完整对象 ID，不能因后台刷新错位。

日志提供查看、比较、文件历史和复制对象信息入口；复制仅在用户主动操作时访问剪贴板，测试使用替身。checkout、revert、cherry-pick、reset、rebase 等写操作必须与普通选择明确区分，按对应分期启用。

### 8.2 控制台与错误

控制台按操作展示开始时间、仓库、目的、阶段、受限的命令摘要、输出、退出状态和重试入口；不是可交互终端，也不启动 shell 等待输入。日志有大小/条数上限，不输出 API Key、口令、凭据 URL、原始环境或整个用户配置。stdout/stderr 有界流式接收；超限、超时、取消和结果未知分别呈现。

认证失败、网络离线、远端拒绝、冲突、hooks/签名失败、权限与锁占用必须有可读原因；详细输出可展开。普通面板收起不等于终止正在进行的提交或推送，运行状态仍可找到。

## 9. 分支、远端与任务切换

顶部入口和日志树共用分支/引用状态，支持搜索、本地创建、从明确起点创建、切换本地分支、由远端分支建立跟踪分支，以及删除已合并且未被使用的本地分支。切换前说明目标；未保存缓冲、会覆盖的本地改动、未跟踪阻挡、冲突或其他 worktree 占用时停止并提供处理入口，不隐式强制切换、贮藏或丢弃。

ahead/behind 基于本地已知引用，显示最近成功获取时间；未获取、过期、无 upstream 和零差异不能混为一谈。打开项目不自动 fetch。提供显式 Fetch、Pull、Push 和远端配置入口；远端新增/修改/删除只作用于明确选择的仓库，凭据部分脱敏。

首批 Pull 建议采用仅快进策略，分叉时保留当前状态并引导后续明确选择 Merge 或 Rebase；不能根据一次按钮点击隐式替用户改写历史。Merge/Rebase 接入后须展示双方、预计动作、冲突/继续/中止状态，不自动执行 stash 或 force push。切换成功后重载受影响的干净文档，刷新项目树、分析器和 Git；删除/移走的打开文件有明确提示，不能保留可误保存回旧分支的缓冲。

## 10. 贮藏、搁置与冲突

### 10.1 贮藏与搁置分开

截图中的“搁置”不能直接当作 Git index 或 Git stash。[WebStorm 官方说明](https://www.jetbrains.com/help/webstorm/shelving-and-unshelving-changes.html)区分 Git 生成的 stash 与 IDE 生成的 Shelf。建议先提供 **“贮藏（Stash）”**，与命令行互通；独立 **“搁置（Shelf）”** 是扩展方案，不冒用相同数据和成功提示。未实现时隐藏或明确禁用，不做可点击的空功能。

Git Stash 需要命名创建、列表、文件/差异预览、应用并保留、应用并删除、显式删除；记录仓库、基线、时间与范围。包含未跟踪文件由用户选择，被忽略文件默认排除；恢复暂存状态是单独可见选项。创建会移动工作版本，须先完成缓冲和版本保护。应用冲突后保留可恢复来源，不能自动删除记录；Git `pop` 冲突会保留 stash，依据 [Git stash](https://git-scm.com/docs/git-stash) 契约核对实际结果。

若后续采用应用 Shelf，需另定私有存储、基线和编码/二进制范围、校验、容量、恢复与删除规则；记录不写进用户源码或 Git 配置，不能依赖公开仓库存放用户补丁。不能将消息草稿或 Git 暂存区命名为“搁置”。

### 10.2 冲突处理

- status 即识别冲突并单独分组；展示正在进行的 merge/rebase/cherry-pick 等操作，普通提交和切分支不能绕过未解决状态。
- 完整目标包含三方基线、两侧输入和可编辑结果的原生合并视图；每侧标明实际提交/分支与含义，rebase 场景不靠固定“我们的/他们的”猜测来源。
- 支持逐块接受一侧/两侧或手动编辑结果；结果复用同一文档、Undo 和保存校验。无冲突标记不自动代表已解决；“标为已解决”才更新 index，再由用户继续原操作。
- 二进制、删除/修改、重命名和子模块冲突提供明确选择或说明暂不支持，不伪造文本合并结果。
- 中止恢复到什么状态、哪些修改会受影响必须具体列出；发生中途失败时先展示实际状态再提供恢复，不能承诺 Git 多文件操作天然全部原子或全部可撤销。

## 11. 与原生文档、Codex 和其他工具协调

每个仓库有单一 Git 状态/任务所有者。提交列表、顶部、日志，以及后续项目树和行标记只消费同一来源的有代次快照；UI 不直接启动 Git 或各自扫描 `.git`。重 I/O、进程等待、差异解析、图计算及索引不在 UI 线程执行；Swift actor/进程分工见 [ADR 0016](adr/0016-native-git.md)，不新增第二个正式文本所有者。

| 操作类别 | 最低保护要求 |
| --- | --- |
| status、日志、固定快照差异 | 后台读取、可取消；变动期间标记快照过期；不运行项目外部助手或写锁刷新来冒充只读 |
| stage/unstage、提交、修改引用 | 同一仓库写任务互斥，执行前复核目标和快照；候选相关保存/编辑不能竞态；不相关缓冲不被隐式保存 |
| 切分支、丢弃、stash、合并及冲突恢复 | 排空在途保存，保护可能受影响的全部文档、组合输入和未保存内容；执行期间冻结相应编辑/自动保存；结束后按实际结果重载 |
| Codex 修改、Pub/package 任务、语义批量修改及关闭流程 | 复用/扩展现有互斥所有者；与 Git 写任务不能同时改同一项目，不复制一套各自看不见的忙碌标记 |

Git 写任务与 Codex 只读任务的重叠也可能让 Agent 读取混合版本；首批采用保守策略：写任务不与任何运行中的 Agent/项目执行任务重叠，提示等待或由用户停止后重试。普通 Git 只读视图可以继续展示有效快照。多个 worktree 共享引用/公共管理目录时还需协调共享写操作，不能只按可见根路径加锁；外部 Git 进程仍需实际 Git 锁与版本检查。

原生 Undo 只对通过原生事务完成的正文修改生效，Git commit、checkout、reset、stash 不能伪装成普通文本撤销。失败、取消、窗口/项目切换和应用退出必须等待自有任务终态或说明结果未知；回收前不能释放文档保护，也不能关闭用户其他应用或按进程名称清理外部 Git。

## 12. 工具执行与资源边界

读操作禁止外部 pager、editor、diff/textconv、fsmonitor、自动对象获取、LFS smudge 或其他未经授权的辅助执行；读取带有此类项目配置的仓库也不能触发它们。需要配置和外部执行的写操作按工作区显式信任处理，不把打开仓库视为运行许可。固定 argv/协议传参，文件名按字面处理，支持空格、中文、换行和以 `-` 开头的路径，不把路径或分支名拼成 shell 命令。

不新增系统钥匙串读写，不读取 HyCode 模型密钥或系统 Codex 登录给 Git 使用；不自动安装 credential helper，不关闭 TLS/SSH 主机校验。远程操作采用可静默失败的认证入口，禁止自动弹出终端/浏览器/系统 askpass。当前仅 SSH 显式操作转发现有 agent socket，并只读现有 known_hosts；不加载私钥/SSH config、不注册新主机。应用自管 Git 凭据尚未接入；无法无交互认证时显示错误，不循环重试或收集系统密码。

以下保留需求阶段的预算目标；当前已冻结的具体值见第 1.2 节，护栏数值不是性能成绩：

| 项目 | 建议护栏与超限行为 |
| --- | --- |
| 并发 | 全局最多两个 Git 读取任务、一个 Git 写任务；同仓库读请求合并，写任务独占，避免与现有分析抢满资源 |
| 历史 | 首批/每页 200 条、内存最多缓存 2,000 条；更早记录继续按需读取，不能把缓存尾部当成历史末尾 |
| 差异 | 输入合计 8 MiB、20,000 行、单行 16,384 UTF-16 单位；超限/特殊来源只读降级。部分候选单文件 8 MiB、合计 32 MiB，不能从省略投影或未保存输入构造 |
| 状态与文件列表 | 分批呈现和虚拟列表，明确加载中/已加载/截断；数量上限、未跟踪扫描范围和重命名检测成本在 ADR 中给出，不静默遗漏 |
| GB 文本/长行 | 受限读取或降级到元数据；不为 Git 差异拼接原生局部页当全文，不全量复制到 SwiftUI；整文件提交仍只来自已验证完整来源 |
| 隐藏与闲置 | 收起工具降低非必要查询，停止滚动预取；有运行任务仍保留可发现状态，项目关闭回收自有任务/观察器/缓存 |

超预算文件允许用户在明确“未完成全文差异审查”的前提下选择完整对象提交，仍核对完整来源和大小；不能将截断差异当提交输入。局部提交必须有完整、可验证的选区基线，降级后禁用。耗时任务显示真实阶段并可取消；本地读取超时和网络超时需分别定义，不能靠无限等待维持按钮忙碌。

性能验收分别记录首次状态、日志首屏/翻页、选文件到差异就绪、增量刷新、取消回收、进程与缓存峰值。首轮采用可分发样本测量后设延迟预算，未测前不宣称毫秒响应、低内存或滚动已流畅。

## 13. 分期与完成定义

**建议第一个日常可用版本包含 G1 + G2；G3 是完整本地审查与协作流程的后续必做项。** 分期不表示删除截图目标，也不作工期承诺。G4 为扩展候选；每期实现、后台验证、真实窗口和性能独立记录，未通过前不因进入下一期而改为完成。

| 阶段 | 范围 | 完成门槛 | 当前状态 |
| --- | --- | --- | --- |
| G0 需求与技术方案 | 本专题、入口索引、Git 选型/事务/信任 ADR 和依赖记录 | 需求可评审，重要语义有案例；护栏与证据可追溯 | 已记录首批采用方案；窗口/认证/性能门槛仍保留 |

首批不承诺托管平台账号/PR/MR 管理、跨仓库一次提交、GitHub/GitLab 专用服务、Git Flow、交互式历史重写或独立 GUI 客户端全部功能；不从截图推导全部 WebStorm Git 功能都已确认。
