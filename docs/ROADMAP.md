# HyCode 实施路线

更新：2026-10-21。首版仅 macOS / Apple Silicon，Swift 原生界面 + Rust 内核。以下为阶段规划，尚无应用工程、工期承诺或性能结果；首个可交付版本具体包含哪些阶段仍需评审。

## 0. 文档与开源基线

项目定名，旧实现已清理。建立 README、文档索引、需求、架构、性能、依赖、能力台账与 ADR，补充 MIT、贡献指南和文档检查，将当前文档基线提交至用户指定的公开仓库。源码公开与应用发布分别记录。

## 1. 原生编辑原型

新建 macOS 宿主与最小 Rust 内核，先验证一个文档会话：打开临时文件、中文输入、选择、撤销重做、安全保存与关闭保护。确定正式缓冲和历史的所有者，比较 Swift/Rust 增量传输及编辑视图成本，再记录绑定和编辑器 ADR。

验收：后台测试和真实窗口分别取得证据；原生 IME、emoji 位置和撤销正确；保存失败、外部修改和取消不丢缓冲。记录首批启动、输入延迟、内存与文件加载数据，作为后续比较基线。

## 2. macOS 工作台与基础编辑

打开目录、项目树、标签、面包屑、最近记录、位置恢复、编码/换行、文档查找替换和项目搜索。高亮、括号/缩进、折叠和多光标按优先级逐项增加。完善外部修改、草稿、窗口及退出保护。

验收：多文档独立历史，Unicode/正则搜索与导航返回；大目录加载、搜索和语法解析期间仍可输入；任务可取消，旧结果隔离。普通文件、大文件、超长行分别测量，按预算降级。

## 3. 一个语言的语义闭环

根据真实使用场景选择首个语言与服务，接通按需启动、增量文档、补全、诊断、悬停、定义/引用和导航历史，再逐个扩展语言。应用实现语言不自动决定首批支持语言。

验收：带依赖项目、未保存缓冲、中文/emoji 位置、过期响应、缺 SDK、离线、崩溃、重启和工作区关闭；服务失败时保留编辑。固定版本与工具链分开记录。

## 4. 项目工具与配套能力

Git 状态/差异、终端、任务和构建逐项设计；调试与扩展单独立项。Markdown/HTML、图片/PDF 和归档根据需求安排，不以扩展格式数量代替编辑质量。

验收：操作与真实文件/工具一致，失败和取消可恢复；写 Git、执行命令和安装依赖具有明确入口，不将打开项目视为执行授权。事务、资源和依赖通知完整。

## 5. macOS 应用交付

在编辑范围和性能预算通过后，完成工具链固定、独立构建说明、依赖通知、签名、公证或所选渠道验证，准备版本、变更说明和真实产物。渠道、最低系统及发布时间目前未定。

验收：源码公开、可构建、后台测试、真实窗口、性能、签名打包、上传与公开下载分别记录。没有完成的阶段保持未验证，不因文档 CI 通过发布应用版本。

## 未来议题

Windows、Linux 和移动端暂不排期，也不在首版工程中建立宿主。跨平台、远程开发、插件兼容及云端能力如需推进，另写需求和 ADR。

## 下一步

继续明确首批用户、语言与版本范围，再评审最小文档原型。本次只整理文档和开源基础，不新增应用实现。真实状态以[能力台账](FORMAT_SUPPORT.md)为准。
