# 大文件文本模式

更新：2026-10-23，build 40。用户确认经常处理超过 1 GB 的文件，因此采用磁盘支撑的分段编辑，不把完整 GB 字符串或全文索引装入 TextKit。适用于所有文本扩展名，包括源代码、JSON/YAML、SQL、日志、Markdown、HTML 与无扩展名文本；图片和视频继续使用各自的只读会话和解码预算。

## 路由与交互

原始文件超过 8 MiB，或前 64 KiB 存在连续至少 16,384 字节（UTF-16 为码元）的长行时，自动进入大文件模式；其他文本沿用原有内存文档。扩展名不参与该判断。支持 UTF-8（可选 BOM）、带 BOM 的 UTF-16 LE/BE。仅按需验证读取的片段，不把未扫描区域宣称为已通过语法或编码检查。

原生编辑区一次读取约 64 KiB，边界避开 UTF-8 标量、UTF-16 代理对和末尾 CRLF；长行关闭自动换行，允许水平滚动。工具条显示原始编码字节区间（不含 BOM）与总大小，提供前/后片段、首/尾、全文件位置滑杆和字节定位。滑杆松开后才读取，不在拖动时排队扫描。行号前加圆点，明确为当前片段行号；尚无全文件行索引、按全局行号跳转或连续虚拟滚动。

工具条的整文件查找为区分大小写的字面搜索，搜索当前未保存逻辑内容，跨块匹配，末尾未命中后从头查找；仅返回一个位置，不积累全文件匹配列表。原生查找栏只搜索当前片段。查找/切片可取消，取消后仍保留原页；历史操作在提交后必须安装配套页。真实菜单、键盘、输入法、拖动和滚动未进行窗口验收。

默认自动保存开关同时控制两种文档。普通文档仍为 800 ms，大文件为停止输入约 3 秒，IME 组合期间暂停。新输入取消尚未提交的自动保存，手动保存继续串行完成。保存始终写出完整逻辑文件，绝不把 64 KiB 页覆盖成完整文件；大文件的保存时间与文件大小相关，需要同目录可容纳完整临时副本的空间。

## 所有权、预算与保存

“连续全文滚动”指滚动到当前范围边缘时自动加载前后内容，不需要使用片段切换按钮；“全局行号”指文件从开头计算的真实行号，例如第 500,000 行，而不是当前片段从 1 开始。这两项需要额外的虚拟视口与后台行索引，尚未实现；build 41 新增的[资源监控](PERFORMANCE_MONITOR.md)不改变现有分段编辑范围。

- Rust `LargeDocument` 独占字节 piece table、修订、当前输入投影和跨页撤销/重做；原生视图只保留当前页，不再建立第二套原生撤销历史。小文件仍由 AppKit 唯一拥有原生撤销。没有新增第三方依赖。
- Swift 文档 actor 串行拥有 Rust 句柄和磁盘基线；原生授权根逐级 `openat`，拒绝符号链接、硬链接、FIFO/特殊文件。Rust 只复制借来的已授权描述符，使用 `pread`，不自行解析路径，不使用可能被外部截断触发 SIGBUS 的 mmap。
- 位置使用 64 位原始编码字节偏移。单页约 64 KiB；当前页及单次 UTF-8 输入限 1 MiB。当前插入数据与历史驻留合计预算 64 MiB、piece 数 65,536；历史最多 128 条且删除+插入逻辑内容合计 32 MiB。历史按预算淘汰最旧记录，不承诺无限撤销。
- 发送给界面的剩余预算同时扣除历史尚需固定的文件片段。界面按修订保守预留新增/删除编码字节及最多三个 piece；旧后台响应不能再次授予后续输入已占的容量。原生单范围和多范围修改均先检查，预算不足时拒绝新输入，已有修改仍可保存。
- 导出前将撤销所需的小片段固定到预算内存；空间不足先按既定策略淘汰旧历史。保存后重基到新 inode，旧完整 GB inode 不被撤销记录持续占用。撤销/重做先准备候选表和新页，全部验证成功才提交修订；不留下历史已改变、界面仍是旧页的状态。
- 导出/查找使用 256 KiB 块；取消令牌可在后台调用中由 UI 线程触发。Swift 负责文件协调、权限/ACL、元数据、版本复核、临时文件、fsync 与原子 rename；Rust 负责完整原编码/BOM 输出和来源版本复核。冲突/取消不覆盖原文件，临时文件清理。rename 后不再响应取消，若恢复编辑状态异常，明确报告已写入的修订并冻结编辑，保留后续未保存页面。

## 分析与预览的范围

大文件使用独立只读片段工作器进行有界 Tree-sitter 高亮，不等待 GB 磁盘保存队列，跨片段的多行结构可能缺少上下文；普通内存文档超过 1 MiB 时按视口片段高亮。仍遵守 65,536 UTF-16 /4,096 捕获及 100 ms 协作预算。大文件不接入全文 LSP、格式化或跨文件修改预览；两处工作区修改入口均拒绝大文件目标，避免把局部页误当完整文档应用全局位置。项目分析仍遵守自己的扫描预算，不能因为编辑器能打开 GB 文件而声称已完整分析它。

Markdown/HTML 的完整静态预览与分段编辑是独立能力：源文本预算从 1 MiB 调整为 32 MiB，输出 HTML 为 64 MiB；不是 GB DOM 渲染。Markdown 在构造解析器前检查结构密度（65,536 个结构标点、100,000 个 CR/LF 字节），再执行既有事件/嵌套/块预算；读取、预检及迭代支持取消，解析库构造中的取消仍为协作式。超限或失败显示明确的预览占位，源码可继续编辑。大文件页与完整预览不做滚动联动，避免伪造全局行/比例映射。离线资源、CSP、网络/脚本限制保持有效，见[预览说明](MARKUP_PREVIEW.md)。

## 源码与静默验证

- `crates/hycode-core/src/large_document.rs`、`large_document_ffi.rs`、`large_document_tests.rs`：磁盘表、预算、历史事务、流式操作与 ABI。
- `packages/HyCodeWorkspace/Sources/LargeFiles/`、`NativeTextDocument.swift`、`TextFileIO.swift`：元数据、输入预留、actor 与协调保存。
- `app/macos/Sources/Editor/LargeFileEditorState.swift`、`NativeTextEditor.swift`、`EditorDocument.swift`：工具条、原生投影与串行生命周期。
- `Tests/LargeTextDocumentTests.swift`、[ADR 0013](adr/0013-disk-backed-text.md)、[后台证据](evidence/2026-10-23-build40-large-files.json)。

常规测试只使用小型自有样本及逻辑 piece-table 的超过 4 GiB 偏移，不反复写入 GB 文件。可单独执行 `nice -n 10 swift build --jobs 2 --product HyCodeLargeFileProbe`，然后 `/usr/sbin/taskpolicy -b nice -n 10 swift run --skip-build HyCodeLargeFileProbe --gib1`。该 Foundation CLI 生成有效 UTF-8 的 1 GiB +4 MiB 文件，以约 64 MiB/s 限速生成，单工作器、固定缓冲；检查整文件查找、首部修改、尾部读取、完整原子保存及流式 SHA-256，退出删除自有临时目录。需至少 4 GiB 空间，最多约 2.1 GiB 临时文件；不使用用户项目、稀疏 NUL 文件、NSApplication、TextKit 或任何窗口。

本轮真实生成样本为 1,077,936,148 字节，64 KiB 返回页，完整保存/预期 SHA-256 一致；探针峰值 RSS 27,099,136 字节。后台首读约 40.69 ms、全文件查找约 6.89 s、完整保存约 1.70 s；包含限速造样/校验总计约 46.99 s。这是刚生成样本和低优先级执行的单次结果，不是冷盘、窗口、帧率、输入延迟或所有更大文件的验收。源码、工具链、命令和包状态以本批证据为准。

最终静默检查为 227 项 Swift（41 组）/33 项 Rust /4 项 Node，系统内容规则编译器回归通过；新增 9 项 Swift 大文件测试通过 Address Sanitizer。Rust 静态库及 Apple 框架未插桩，当前只有稳定 Rust 工具链，未安装 nightly sanitizer；无 GUI 的结果不能代替实际输入、窗口和跨平台验收。Release 本地开发包为 0.1.0 / build 40，arm64，构建但未启动、安装、签名分发或提交推送。
