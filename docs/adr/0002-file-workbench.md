# ADR 0002：SwiftUI/AppKit 文件工作台与 Rust 目录 C ABI

- 状态：已采用；静默构建与后台测试通过，真实窗口待验证
- 日期：2026-10-21
- 范围：[当前文件浏览工作台](../WORKBENCH.md)

## 背景

用户要求先搭建 IDEA 风格基础交互和布局，只需浏览文件列表，分析器暂不接入。测试必须静默，不能启动 GUI 或操作用户桌面。

## 决策

1. 使用 SwiftPM 管理 macOS 宿主与可测试工作区模型。SwiftUI 组织工作台，AppKit NSOutlineView 承担项目树；build 8 按用户要求移除初始目录 Table，目录只在树内浏览，中央仅创建文件标签；不引入网页 UI 或编辑内核。
2. Rust 当前只负责单层只读目录枚举、元数据、排序、路径和符号链接策略。C ABI 1 通过 UTF-8 参数与 JSON 结果接入，不引入生成绑定工具。
3. Swift 的 MainActor 维护 UI/导航/请求代次；最多两个后台工作器通过共享 FIFO 负责阻塞 FFI 与解码（build 8 从单工作器改为有界并发）。独立原子取消令牌可跨线程取消，令牌和返回字节均按 C 头文件及 Swift RAII 释放，不跨 ABI 传递 Rust 内部布局。
4. 声明部署目标 macOS 14 / Apple Silicon；当前验证工具链为 Swift 6.4 / Xcode 27.1、Rust 1.96.0。Bundle ID 为 `io.github.hhcme.hycode`，初始开发版本 `0.1.0` / build `1`，后续构建号见[工作台说明](../WORKBENCH.md)。其他系统运行需另验。
5. 构建脚本生成本地 `build/HyCode.app`，不启动、不安装、不做分发签名。Swift Testing 只运行 Foundation/工作区模型，无应用宿主或 UI 自动化。

## 影响与限制

用真实文件读取验证 Swift/Rust 生命周期，同时将范围限制在目录浏览。临时标签、固定标签、历史和文件信息可先验模型语义；真正的视觉、原生焦点和桌面行为仍未验证。

目录枚举有数量与扫描上限，显示截断和跳过项，不自动递归。符号链接只显示不跟随，路径检查不宣称是防并发重命名的沙箱。目录总缓存预算及文件监听后续设计。build 8 已加入最多 30 条本地最近项目与可选系统访问书签；build 18 按用户要求默认恢复上次打开的项目，显式关闭可清空启动项但保留历史。书签生成/解析离开主线程且恢复不弹 UI，权限恢复尚未窗口验证。

这不是文本缓冲、编辑事务或语言服务的 ABI 决策。当前路径身份足够用于只读浏览；以后需要重命名、文件监听和编辑会话时另建文档身份契约，不直接把显示路径当成正式文档身份。

实际采用的序列化依赖、标准库通知见[依赖台账](../DEPENDENCIES.md)和[第三方通知](../../THIRD_PARTY_NOTICES.md)，高亮与分析器候选继续保持未接入。
