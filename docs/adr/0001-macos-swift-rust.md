# ADR 0001：首版 macOS、Swift 原生界面和 Rust 内核

- 状态：已接受（用户确认的方向）
- 日期：2026-10-21
- 关联：[方向记录](../EDITOR_DIRECTION.md)、[技术设计](../TECH_DESIGN.md)、[性能设计](../PERFORMANCE.md)

## 背景

HyCode 在删除旧文件浏览器实现后从零重写。用户确认首版只做 macOS，使用 Swift 原生开发，以 Rust 作为内核，面向高性能代码编辑并完全开源，允许复用官方和社区开源组件。

## 决策

1. 首版目标为 macOS / Apple Silicon，不建立其他平台宿主或对等交付要求。
2. Swift 负责原生界面和系统交互，Rust 承担编辑核心及后台能力；模块保持单一所有者和清晰生命周期。
3. 原生输入、系统菜单、快捷键与无障碍属于产品要求；系统 WebView 不承载整个编辑器。
4. 性能通过本项目实际测量验证，依赖可组合使用，不要求所有底层组件由 Rust 编写。
5. 原生界面、核心、桥接、构建和文档全部纳入公开源码。根许可和贡献安排见 [MIT](../../LICENSE) 与[贡献指南](../../CONTRIBUTING.md)；第三方许可单独管理。

## 理由与影响

聚焦一个平台使首批验证集中在原生编辑、输入与 Swift/Rust 边界，避免在编辑闭环尚未建立时增加多个宿主。公开源码应能由贡献者独立获取和构建，不要求私有项目、账号或后台。

需要验证原生编辑视图与 Rust 文档服务的增量协作、Unicode 位置、撤销及线程生命周期。不能由 Rust 的选用直接推导已达到性能目标。

## 本决策没有确定的事项

本决策接受时，SwiftUI/AppKit 组合、缓冲所有权、编辑视图、FFI、系统与工具链、首批语言、依赖版本、性能预算和分发均未定。后续浏览工程已在 ADR 0002 选择界面组合、目录 ABI、部署目标及工具链；正式文本缓冲、编辑视图、分析器和应用发布仍需原型与评审。

本决策接受时只有文档。后续文件浏览工程与 C ABI 选择记录在 [ADR 0002](0002-file-workbench.md)，编辑缓冲和分析器仍未定案，按[路线](../ROADMAP.md)逐项验收。
