# HyCode 性能设计与验收

更新：2026-10-21。高性能是首版要求。目前已有文件浏览工作台和后台测试，但没有真实窗口性能测量或已接受的数值预算；本页定义测量方法，不作性能已达标的声明。

## 测量原则

首版只测 macOS / Apple Silicon。记录机器型号、内存、系统、屏幕刷新率、工具链、构建配置、提交、样本哈希及语言服务状态。Debug 调试和 Release 测量分开，冷启动与热启动分开，不把依赖自身的 benchmark 当成整机应用结果。

同一操作重复测量，记录次数、中位数及尾部延迟；输入和滚动至少关注 P95，样本不足时保留原始数据并说明限制。对比方案使用相同输入、环境和交互路径。

## 可分发样本

- 普通源码、频繁小编辑、多标签，以及带依赖的小项目。
- 中文、emoji、组合字符、CRLF/LF、不同编码和无末尾换行。
- 按大小分档的纯文本、单行极长文件、大量短行文件；尺寸与上限在原型阶段确定。
- 大量小文件、深目录、被忽略目录、慢磁盘或权限失败；所有样本由临时目录或可公开生成方式提供。
- 开启/关闭高亮、搜索及语言服务分别测量，避免隐藏后台工作。

不拿用户真实项目做破坏性测试。所有测量遵循[静默测试规则](DEVELOPMENT.md)，控制 CPU、内存、I/O 与并发，不影响用户前台响应。只执行能够确认不启动 GUI、不操作桌面的后台测量；真实输入、滚动、窗口启动和绘制测量保留为未验证，后台 benchmark 不能替代这些证据。隐藏启动或独立数据目录不构成执行这些测量的依据。

## 设计约束

- I/O、解析、扫描和索引离开主线程，任务可取消，避免过期结果改写当前文档。
- Swift/Rust 按修订传输增量与必要片段，避免每次输入全量复制；正式缓冲和历史各有单一所有者。
- 可见区域按需布局与绘制，控制高亮、缓存和服务的内存/CPU 预算。
- 内存 Rope 不等于超内存编辑；超预算时明确只读、部分预览或拒绝原因，不把截断内容写回原件。

## 高亮滚动调度（build 23）

用户反馈 build 22 反复滚动后新区域仍无色。源码确认每次滚动重启延迟并作废在途结果，且每次结果清除上一屏颜色；build 23 改为单任务持续读取最新视口、附近预取和至多 8 段颜色覆盖缓存，编辑等修订变化仍清除旧色。连续事件、缓存边界与失败后追最新范围由后台状态测试覆盖，不是模拟用户桌面事件。

完整后台测试中另观察生成的 4,000 行 ASCII Dart 临时文件：同一文档依次查询 5 个分散视口，Rust release + Swift Debug 的桥接请求约为 5.747、0.681、0.657、0.671、0.688 ms。共享语法缓存可能已被其他测试预热；这些单次观测没有独立冷启动或等输入 A/B 基线，不包含 TextKit 排版、颜色属性应用及屏幕显示，不能作为实际滚动延迟或 FPS。样本生成规格、哈希、环境、源码和原始数值见[后台记录](evidence/2026-10-21-build23-syntax-viewport.json)，真实窗口颜色延迟与帧率仍未验证。

## 预算与结果记录

数值预算在首个原型测量后结合目标使用场景评审，以 ADR 或本页更新记录。尚未定案的预算保持“待定”，不编造启动毫秒数、内存占用或无限文件大小承诺。

每条结果至少包含：日期、提交、环境、配置、样本与哈希、操作步骤或命令、重复次数、数据及统计、后台/窗口分类、限制和回归结论。取得第一份真实证据后，再建立对应结果文件并更新[能力台账](FORMAT_SUPPORT.md)。

## 工作台拖动诊断现状

build 7 已为布局、宿主尺寸变更、工具位图缓存未命中及停靠提交加入可选 `Workbench` signpost 区间，默认没有主动采集或报告文件，不包含文件名和路径；源码位置见[工作台说明](WORKBENCH.md)。后续实际采集仍遵循静默约束和授权范围，区间本身不代表完整屏幕帧耗时。

已去掉重复插入槽的整工具栏重绘、相同像素矩形的重复宿主更新及逐帧 tracking area 分配，完整拖拽位图与 glyph 有界缓存。纯位图测试属于离屏正确性验证；这些源码改动没有确定偶发卡顿的根因，也没有提供实机 FPS、P95 延迟或已达标结论。

## 目录读取探针（build 8）

[DirectoryProbe](../tools/DirectoryProbe/main.swift) 仅链接 Foundation/工作区与 Rust C ABI，不创建 NSApplication、窗口或测试宿主。默认生成并清理临时目录：64 个 5 字节文件、8 个空目录；以低优先级连续读取根目录 7 次，不递归扫描，不接触用户项目。显式 `--path` 才会读取调用者指定目录；本轮没有使用该参数。

```sh
bash scripts/build_core.sh
nice -n 10 swift run --jobs 2 HyCodeDirectoryProbe
```

2026-10-21、Mac16,11 / 48 GiB、macOS 27.0.1、Swift Debug + Rust release 静态库、未提交的 build 8 工作区：72 项临时样本 7 次读取，中位数 **0.394 ms**，最大 **1.027 ms**。包含排队、Rust 单层枚举/元数据/排序、JSON 和 Swift 解码。原始样本、生成规格/哈希、源码哈希与环境见[后台记录](evidence/2026-10-21-build8-directory-read.json)。构建与读取均限制在后台，本轮未启动应用。

这只是小样本、热文件系统缓存的串行读取，没有旧版本等输入基线，不测并发吞吐、用户目录、冷磁盘、文件树布局或屏幕呈现。因此不把毫秒内读取推导为用户目录应有相同速度，不宣称 FPS 或整机提速。本轮修复的是可静态确认的串行队头阻塞、全树重载和刷新展开遗漏；还加入 `TreeBranchReload` 可选 signpost，真实界面耗时尚未采集。

## 树宽度缓存（build 9）

树列宽随展开内容而变，文字宽度按节点缓存，子树最大值按分支失效；分隔拖动只应用缓存和视口宽度，不重新遍历树或测量字体。首次展开新增节点仍由 MainActor 测量文字，其在大目录中的耗时尚未采集，不把缓存实现称为首次展开或滚动已经流畅。原生完整文字、双轴滚动和缩窄/折叠边界目前只有编译与源码复核，未进行真实窗口性能验证。

## 分隔拖动收口（build 11）

本轮把高频指针请求保留为最新一项，在 displayLink 回调中直接提交原生几何，避免回调后另等一轮 needsLayout；不调用 layoutSubtreeIfNeeded 强制重排所有宿主。隐藏宿主保留内容尺寸，同停靠/同项目的 root 更新在拖动结束合并提交。单一高亮图层与统一交互状态处理松手、取消、失焦和漏收 mouseUp，迟到的 enter 不再重亮。

`ResizeDisplayTick` 和 `HostRootUpdate` 与已有 `CanvasLayout`、`HostContentResize` 配合，后续可区分几何提交、根内容重绑和宿主尺寸调整。它们仍是按需区间，未自动采集。9 项事件序列/几何模型测试提供收尾与合并的后台证据；没有创建 AppKit 窗口或测量实际帧率、端到端拖动延迟、GPU/显示时间，不把这些改动宣称为实机卡顿已消失。实际 CPU 热点仍需遵守静默约束另取证。

## 目录展开准备（build 16）

目录 I/O 与显示准备分开：目录服务继续使用两个有界后台读取工作器；新 `ProjectTreeText` 使用一个非 MainActor 工作器准备常规文件名宽度，CoreText 不创建 NSApplication 或窗口。普通节点不在展开回调中逐个执行 NSString/NSFont 测量，根路径及短状态行仍保留 AppKit 测量。系统图标按固定符号复用，恢复逻辑跳过已展开项。此举去掉了明确的主线程同步工作，不是对用户项目首次停顿的完整归因。

后台探针仍使用默认 72 项临时目录、7 次串行读取，新增独立的文字准备计时。2026-10-21 本轮记录：读取中位数 0.385 ms、最大 1.398 ms；文字准备首批 9.638 ms，随后 6 批为 0.810–0.938 ms。文字准备包含工作器调度、CoreText 字体与名称测量，不含 AppKit cell、布局、系统图标首绘或屏幕呈现，也不是操作系统冷启动数据。首批准备成本现在位于后台。

同期旧探针的等规格临时样本读取中位数 0.265 ms、最大 0.852 ms，仅作原始观测保留；Rust 读取实现没有改动，这组小样本不能说明 I/O 提速或回退，更不能作为整机 A/B。4 项新增 CoreText 测试只验证测量结果与取消/隔离正确性；没有实际 FPS、主线程耗时或点击到呈现的数值。[本轮记录](evidence/2026-10-21-build16-scroll-expand.json)保留原始样本、源码哈希与验证范围。
