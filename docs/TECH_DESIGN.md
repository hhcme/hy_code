# HyCode 重写技术设计

更新：2026-10-21。首版确定为 macOS / Apple Silicon、Swift 原生界面 + Rust 内核。当前已有文件工作台和基础文本编辑，真实入口见[工作台说明](WORKBENCH.md)、[编辑说明](EDITING.md)及 [ADR 0003](adr/0003-text-editing.md)。解析、语言服务、跨文件事务和大文件方案仍为后续设计。

## 分层与职责

| 层 | 建议职责 | 边界 |
| --- | --- | --- |
| Swift 原生宿主 | macOS 窗口、项目树、编辑视图、工具窗口、IME、菜单、无障碍 | 不承载重型扫描、解析或索引 |
| macOS 系统适配 | 文件授权/监听、系统剪贴板、文件协调、进程与终端、原生预览 | 明确系统授权、文件身份和访问生命周期 |
| Rust 内核 | 工作区、文档身份与事务、搜索/解析调度、后台任务、状态持久化 | 不创建窗口，不依赖某一 UI 框架 |
| 引擎与服务 | 语法解析、LSP、Git、归档、调试适配 | 按需加载，可取消，可降级，独立记录许可与版本 |

项目按能力逐步建模块；编辑、工作区、文件访问、后台任务和服务生命周期分别明确所有者，避免跨模块全局状态或 UI 直接调用解析器。

## 文档、缓冲与撤销

当前由 Rust TextDocument 管理正式文本和修订；AppKit TextKit 1 视图保存输入投影与选择/滚动状态，通过 NSTextStorage 精确传递 UTF-16 增量。每文档原生 UndoManager 独占撤销历史，Rust 不再建立第二套历史。非 MainActor 的 NativeTextDocument actor 串行拥有句柄与磁盘基线并执行文件 I/O；UI 以有序任务提交编辑和保存。默认 800 ms 自动保存，可在设置关闭。实现和边界见 [ADR 0003](adr/0003-text-editing.md)。

无论最终采用哪种存储适配，只允许一个正式缓冲与撤销历史的所有者；原生输入组合态可暂存在平台层，提交为可追溯事务，不能让平台 UndoManager 和 Rust 各自独立重放同一次编辑。Swift/Rust 传递按修订号定位的增量和所需片段，避免每次输入或光标移动都复制整篇文档；缓存不得成为第二个独立可写的正式缓冲。文件身份与显示路径分开，重命名、别名、工作区关闭与服务响应统一按会话身份处理。

保存基于文档修订与磁盘版本检查，平台文件协调/临时写入/落位失败保留缓冲。外部修改不能静默覆盖。预览的截断文本不得作为完整保存输入；草稿、文件内容与工作区布局分别持久化，明确格式版本与恢复路径。

## 后台任务和大文件

任务具有 ID、代次、进度、取消、终态和清理责任；UI 只接收当前会话有效的结果。I/O、搜索、解析、索引和格式解码离开 UI 线程；使用 async 本身不能证明同步工作已离开主线程。

按需读取、分页/分块和增量解析，不把整个工作区一次加载到内存。已知总量显示真实进度，否则显示阶段与转圈；取消后阻止旧响应和旧任务改写新会话。索引和缓存设资源预算、失效及回收策略，不复制外部项目的固定阈值作为本项目上限。Rope 等内存数据结构不自动提供超内存文件的编辑能力；大文件模式和边界单独设计。测量规则见[性能设计](PERFORMANCE.md)。

## 平台与绑定建议

| 首版目标 | 方案 | 状态 |
| --- | --- | --- |
| 界面实现语言 | Swift | 已建立 macOS 文件浏览工程 |
| 工作台 | SwiftUI + AppKit NSOutlineView / TextKit 1 | 文件浏览与基础编辑已实现，窗口未验证 |
| 编辑内核 | Rust 文本缓冲、修订、编码和只读目录枚举 | 基础文本编辑已接入，分析器未接入 |
| Swift/Rust 桥接 | 窄 C ABI 1 + Swift actor 包装 | 目录与增量文本接口已接入并完成后台测试 |

首版只验证 macOS / Apple Silicon，不建立其他端宿主。当前部署目标 macOS 14，验证编译器 Swift 6.4 / Xcode 27.1、Rust 1.96.0；旧系统与真实窗口运行尚未验证。系统 WebView 不承载工作台。

FFI 契约需说明对象、句柄和字符串的所有权，长度与位置编码，调用线程与并发模型，回调注销、取消、错误和释放责任。若采用 C ABI，使用不透明句柄及清晰的分配/释放配对，不暴露 Rust 内部布局；panic 不穿越 ABI。结果按文档会话与修订判断有效性，UI 回调切回主线程。生成绑定不手改；macOS 宿主验证 ABI、打包和生命周期。

## 服务与工作区

工作区保存用户授权、目录根、文档身份、工具链和范围。LSP 作为独立长生命周期服务，由管理器处理启动、协议、取消、崩溃、空闲回收和关闭；文档位置按协商编码转换，所有请求绑定修订。终端、Git、调试和任务采用独立适配，不让一次文件预览默认启动整套工具。

当前目录读取由两个后台 actor 通过共享 FIFO 限定并发，不让一个慢目录阻塞全部请求；取消令牌跨线程置位，但正在执行的系统文件调用仍须等待返回。排队取消也要等一个工作器空闲才能结束。MainActor 按目录修订刷新 NSOutlineView 的变化分支；刷新后显式恢复可见展开分支的读取，不依赖原生重复展开回调。目录选择与文件标签分开建模，不维护中央目录表格。

最近项目由 Swift 工作区拥有，最多保存 30 条标准化路径、徽标派生数据和可选访问书签；书签生成/解析离开主线程，访问仍由 WorkspaceAccess 管理并被在途任务保活。读取失败保留原位错误与重试，不把记录路径视作永久授权。

同一记录保存可空的启动项目路径：打开更新，显式关闭清空；旧数据缺少字段时迁移历史首项，显式空值不会重新迁移。场景首次出现只尝试恢复一次，用户主动打开/关闭/切换会消费恢复机会；后台解析结果仍按项目意图校验，不能覆盖较新的操作。不新增第二个工作区或文件访问所有者。

当前已把 Rust 内核、macOS 宿主、C 头文件、Swift 包、测试和工具分开组织，源码地图见[工作台说明](WORKBENCH.md)。基础编辑与保存已接入，没有创建分析器、Git 或终端服务；工作台现有这些工具的可停靠空面板入口，不代表对应功能已实现。实际依赖与候选按[依赖台账](DEPENDENCIES.md)分别管理。
