## 2. 默认后台验证

- 默认运行不启动应用、窗口或模拟器的构建、静态检查和单元测试。
- 原生应用、模拟器、系统菜单、文件选择器、分享面板、真实键鼠、截图和剪贴板检查属于交互测试，在用户明确授权的范围内执行。
- `open -g`、隐藏启动、独立数据目录或直接运行可执行文件都不能保证静默、不抢焦点，不能用来绕过交互边界。
- 交互检查保留真实断言，独立命名和报告；不删掉输入、焦点等断言后称为通过。
- 未获授权时继续源码和后台验证，说明未覆盖项；不擅自启动、关闭、覆盖或重启应用，不改其他项目的固定包。
- 本节替代 2026-10-19 文档中“后台启动即可静默”的建议。

## 3. 共享核心与文件所有权

- 共用 Rust 领域逻辑、格式接口、错误语义、任务与编辑事务；平台层负责原生 UI、系统权限、渲染和生命周期。
- 绑定由源定义生成，记录版本与步骤，遵循忽略规则，不手改生成文件。
- FFI 说明对象所有权、编码、长度、线程、取消、回调注销、错误和释放责任。
- 大文件使用流、句柄、分页或按需渲染；工作预算与功能上限分开记录，不把截断文本回写成完整文件。
- 默认编辑库内副本；来源路径不是修改原件的权限。保存、导出和未来原位置工作区明确区分。

## 4. 样本与验收

- 测试用独立临时目录和可分发样本，不修改用户真实文档、Git 仓库、系统入口或文件关联。
- 台账记录引擎/版本、平台/架构、样本来源及许可、格式变体、命令、输出哈希和限制。私人文件不提交入库。
- 按功能验证中文名、编码、超长行、多页、加密、损坏、取消、空间不足、冲突与恢复。
- 归档处理校验输出路径、链接、嵌套和异常膨胀；失败/取消不破坏原件和已存在目标。
- 只改文档时检查链接、状态一致性和 diff，不启动应用或无关 GUI 回归。
- 核心变化验证相关 Rust 用例及往返；涉及绑定再验证对应宿主。内存、并发和解析边界变化按需补 sanitizer、竞态及异常样本检查。
- 各端分别记录构建、ABI、实机、签名与上架结果，共享核心测试不代替平台验收。
