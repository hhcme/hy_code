# 分阶段实施

> **2026-10-21 编辑器方向更新**：最新定位改为轻量、原生、完全开源的代码编辑器，借鉴 IDEA 界面组织。先读 [新方向与优先级](EDITOR_DIRECTION.md)；本文旧文件浏览器主线、强制复制入库、付费解锁及商店优先规则遇冲突时仅作历史记录。候选能力和骨架实现状态仍需分别看待。

更新日期：2026-10-21。本页是基于独立全端方向的推进建议，不是所有格式/端的完成承诺或正式工期。阶段可迭代，兼容性以[能力台账](FORMAT_SUPPORT.md)为准。

## 0. 基线与当前状态

已有 macOS SwiftUI + Rust/UniFFI ZIP 列目录骨架、复制入库和最近记录 JSON。尚无通用预览、编辑、解压/创建、LSP、Git 及其他平台宿主。本轮只调整文档，未移动代码、增添依赖、启动应用、构建、打包、发布或提交推送。

## A. 补齐共享基础与文件库

- 给现有同步复制、ZIP 打开/全量枚举建立后台执行、任务进度和取消；先解决 UI 响应，再扩格式。
- 建立稳定文件身份、文档会话、格式能力、任务及平台访问契约，保留来源与库内副本语义。
- 实现目录导入、目录/标签组织、最近文件/目录、分页；现有 JSON 有版本迁移和失败恢复。
- macOS 文件库网格/列表、快速预览、标签工作台及返回位置先形成完整交互；窄窗口和加载态可用。

完成依据：大目录/复制/ZIP 枚举时 UI 不阻塞；取消与中断后数据一致；重启可找回记录与位置，不改外部原件。

## B. 通用预览与归档闭环

- 文本、Markdown/HTML、图片、分页 PDF，以及适用的系统预览兜底；HTML 本地资源、脚本/联网策略明确。
- ZIP/RAR/7z 等按引擎逐项接入浏览与解压，ZIP/7z 创建优先验证；其他归档按真实场景扩展。
- 包内文件按需提取预览，任务有进度、取消、磁盘错误和结果入口，不要求手动全量解压。
- 验证 64 位大小/偏移、ZIP64、超过 4 GiB 的真实条目/包、中文/旧编码、密码、损坏、嵌套、路径和链接风险；不把某次大样本当作无界证明。
- 桌面系统右键和紧凑任务窗可作为独立子阶段；先决定快捷归档是否入库及输出语义，再做系统扩展。

完成依据：所列格式建立本仓可复现台账；列表/预览保留浏览位置，大文档不堵主线程，输出内容与往返哈希正确。

## C. 普通编辑与代码基础

- 原生文本/代码编辑，行号、缩进、注释/括号交互、查找替换、撤销重做与高亮；库内副本安全保存和显式导出。
- Markdown/HTML 源码编辑与分栏预览，保护中文组合输入和光标/滚动。
- 草稿、脏标签关闭、退出、只读、外部修改、编码往返和失败恢复；预算超出时只读，不保存截断内容。
- 增量高亮/结构解析候选验证，不机械继承 HyHub 的 2 MiB 编辑或 64 KiB 着色预算。

完成依据：原生输入和保存事务分别通过后台/交互验收；异常保存不丢内容，未支持格式明确降级。

## D. 桌面项目与语言服务

- 先明确项目目录入库与原位置工作区的所有权；不能让单文件导入伪装成完整项目。
- 先用一个语言服务跑通生命周期、工作区、文档版本、取消、错误/崩溃降级；再扩展候选语言。
- 补全、悬停、参数、定义/实现跳转、引用列表和导航返回；诊断、格式化、自动导入、重命名按事务能力递进。
- 工具链获取、项目信任、索引范围、离线行为、包许可和桌面渠道分别核对。
- Git 先评估只读状态/差异的正确语义；暂存、提交、分支、拉取/推送不作为本阶段默认范围。

完成依据：真实带依赖项目、未保存缓冲、中文/emoji 位置、导航返回、旧响应、缺 SDK、离线、崩溃及索引响应通过。某语言可用不代表全部语言可用。

详见 [CODE_INTELLIGENCE.md](CODE_INTELLIGENCE.md)。

## E. 全端宿主与原生交互

本阶段在共享文件契约稳定后可与 B/C 部分并行；不要求所有移动端等待桌面 LSP 全部完成。建议先从已有 Apple 核心链路验证 iOS/iPadOS，再逐个建立其他宿主；实际顺序待细化。

| 平台 | 首批验证重点 |
| --- | --- |
| iOS/iPadOS | 新 target/切片、导入与分享授权、触控/分栏、后台中断、内存、原生编辑 |
| Windows | 原生宿主、C ABI/.NET、路径与链接、文件关联/右键、窗口与签名 |
| Linux | 原生宿主、Wayland/X11 目标、文件门户/权限、桌面入口、字体与渲染差异 |
| Android | ABI 包、UniFFI、文档 URI、分享、多窗口/生命周期、内存与后台限制 |
| HarmonyOS NEXT | ArkUI 宿主、Rust/Native API、文件授权、生命周期、真机与渠道 |

每端先交付库/导入、代表性预览、归档及基础编辑闭环，再扩格式和增强能力。底层库能编译、模拟器能启动、真机兼容、商店可发布分别记录。

## F. 扩格式与发布准备

- 在办公、电子书、媒体、数据库、设计与图纸/三维等类别补真实样本和合适引擎，避免仅堆扩展名。
- 单独评估可视化编辑、批注、OCR、转换及专业 SDK；不从通用浏览范围自动扩成完整专业创作套件。
- 各端确定最低系统、架构、渠道、体积、引擎通知、商业模式与版本策略，分别打包和发布。
- Apple 保留先只走商店的约束，其他平台另做渠道准备；旧双平台工期不作为全端排期。

## 当前建议的下一项实施

从 A 开始：为现有入库和 ZIP 目录链路补后台任务/取消与文档会话，再做快速预览和文本/PDF 等代表性格式。先形成可用文件工具，再逐步进入项目级代码能力；本轮不自动开始这些实现。
