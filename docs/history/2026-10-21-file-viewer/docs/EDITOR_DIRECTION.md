# 原生开源代码编辑器方向

更新：2026-10-21。本文记录最新用户指示；与此前万能文件浏览器定位冲突时，以本文为准。产品正式名称尚未选定，`hc_file_viewer` 暂为工程目录和构建标识。

## 已明确的产品目标

用户要求把项目改为类似 VSCode 与 IDEA 的开发工具：追求 VSCode 式轻量体验，采用 IDEA 式界面风格，继续使用原生界面 + Rust，并成为完全开源项目。原有 ZIP 浏览骨架仍是当前实现，不代表已具备编辑器、项目系统或语言服务。

目标定位为**轻量、原生、可扩展的开源代码编辑器**，逐步增加项目级 IDE 能力。代码编辑和项目工作区成为主线；通用文件预览、归档与整理作为配套能力，逐项复用，避免格式扩充阻塞编辑器闭环。

## 建议的体验基线

- 桌面端先行：macOS 骨架验证后扩展 Windows/Linux；移动端保留长期规划，独立设计交互与能力范围，不承诺与桌面 IDE 同时达到功能对等。
- 首页提供最近项目、打开文件和打开目录；主界面由项目树、标签编辑区、可折叠工具窗口和状态栏构成。借鉴 IDEA 的信息组织、紧凑间距、分组和层次，保持各平台原生菜单、输入法、快捷键及无障碍行为。
- 轻量需要实际测量启动、空闲内存、输入延迟及大项目响应。语法解析、索引、语言服务、Git 和终端按工作区需要启用；后台任务可取消，不在启动时装载所有语言工具链。具体预算在原生编辑器原型测量后确定。
- 桌面项目建议以用户选定的原位置目录为工作区；打开和保存直接针对已授权文件。旧“所有文件一律复制入库”不再作为新编辑器的强制规则。复制导入可用于独立资料与移动端，但必须与原位置工作区清晰区分。此为目标设计，现有 LibraryStore 行为未改变。
- 编辑基础先完成选择、输入法、撤销重做、编码/换行、原子保存、外部修改冲突和脏标签保护，再接高亮、查找替换、多光标及项目搜索。
- 代码智能复用逐项核验的语言服务，通过 LSP 接入补全、悬停、诊断和定义/引用跳转。先打通一个语言的完整生命周期；调试通过 DAP 等独立能力后续评估。
- Git、差异、终端、构建任务与扩展接口属于编辑器路线，按阶段推进。开放项目不等于自动执行项目脚本、安装依赖或启动不受信任的工具链。

## 技术与开源边界

原生 UI 和平台适配负责窗口、编辑视图、文件授权、系统交互和无障碍；Rust 负责共享文档缓冲、编辑事务、搜索/解析调度、任务、工作区与格式处理。沿用已有 SwiftUI/AppKit + UniFFI 骨架，其他平台框架仍按技术设计逐端验证。系统 WebView 可承担 HTML/Markdown 预览，不承担整个编辑器界面。

完全开源的目标覆盖编辑器界面、Rust 核心、平台桥接、构建脚本和开发文档，公开功能不依赖私有编辑内核或必须登录的私有后台。开源不等于全部第三方二进制都能再分发；依赖和随包语言服务逐项记录许可、来源、版本与构建方式。

当前没有根许可证，也没有远程仓库；“完全开源”目前是用户确定的方向，尚未完成对外发布。根许可证、版权归属、贡献约定、公开仓库地址及渠道需在公开前确定。本文不擅自添加许可或改变仓库可见性。此前付费解锁作为历史讨论，不作为新编辑器的默认产品要求；是否接受捐赠、提供商店分发另定。

先前 App Store / Mac App Store 专项是历史研究，不直接决定桌面 IDE 的新分发方案。保留现有 macOS Apple Silicon 骨架，不自动扩展架构。命名、Bundle ID、包名、FFI 标识、应用数据迁移和发布渠道应在方案确定后一起调整。

## 实施顺序建议

1. 原生编辑器外壳：最近项目、目录树、标签、面包屑、工具窗口布局与状态恢复；跑通真实目录和文档身份。
2. 可安全保存的文本编辑：原生输入、独立撤销、查找替换、外部冲突、脏标签和崩溃草稿恢复，测量性能。
3. 高亮与项目搜索；一个语言的 LSP 补全、诊断及定义/引用闭环，服务按需启动和释放。
4. Git 差异、终端和任务，再评估调试与扩展体系；逐步迁移预览和归档模块。
5. 验证跨端宿主和原生交互；整理可复现构建、依赖许可、贡献文档与各端发布证据。
